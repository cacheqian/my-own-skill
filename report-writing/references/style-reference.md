# 视觉与排版规范

制作关键图或排版富文档时阅读。以下是可调整的默认建议；用户指定的结构、平台能力与品牌规范优先。

## 文字与页面格式

| 位置 | 建议做法 | 目的 |
|---|---|---|
| 核心定义 | 一句加粗定义，必要时放入浅色提示块 | 让读者先知道对象与用途 |
| 术语 | 首次出现时紧跟简短解释 | 解释一次，后文保持同一称呼 |
| 核心价值 | 短列表，以加粗价值标签开头 | 用收益引领说明，避免堆功能名 |
| 章节 | 稳定的两级标题，第三层按需 | 沿用用户编号，让层级承担导航 |
| 重点 | 加粗结论、关键数字和行标签 | 保留强调差异，避免整段加粗 |
| 表格 | 窄标签列、宽说明列，表头浅灰，内容顶端对齐 | 便于比较并保持正常阅读宽度 |
| 界面说明 | “功能／能力说明／交互示例”，示例紧邻对应功能 | 让说明与实际操作对应；无信息增量则省略截图列 |
| 参考资料 | 末尾按用途列背景链接，关键证据贴近结论 | 减少正文展开，同时便于追溯 |

One-page 风格侧重快速建立整体认知；仅当用户明确要求一页纸时，才按实际页面尺寸控制篇幅，不通过小字图片塞入整篇报告。

## 按解释任务选择图

| 图的任务 | 可选构图 | 需要回答的问题 |
|---|---|---|
| 建立整体认知 | 紧凑分层或分区，必要时补反馈回路 | 有哪些层级，如何协作，边界在哪里 |
| 展开运行机制 | 主流程或泳道，必要时标出分支、异常与反馈 | 谁触发，谁执行，结果回到哪里 |
| 说明贯穿保障 | 一条主流程，下方放贯穿能力与后续缺口 | 主流程如何得到支撑，哪些能力尚未具备 |

关系必须来自材料。跨步骤的保障能力可以放在流程下方，不机械连成顺序步骤；独立执行的机制也不画成主流程必经环节。

短篇通常 1～2 张关键图足够。增加图前检查其是否回答新的问题；现有图之间若有重叠，可合并或将次要内容移入表格。复杂材料可以增加图，但每张图都应有独立用途，不照搬固定数量或节点清单。

## 默认配色

以下色值可直接用于简洁的业务汇报；无需为还原颜色改变平台默认字号或影响可读性。

| 用途 | 建议色值 | 使用方式 |
|---|---|---|
| 主文字 | `#1F2329` | 标题、模块名、核心内容 |
| 辅助文字 | `#646A73` | 短说明与次级标签；关键条件不要灰到难读 |
| 主强调／当前链路 | `#3370FF` | 关键描边、流程编号与主线 |
| 浅蓝区域 | `#F0F5FF` | 同类模块或保障能力的分组背景 |
| 浅灰分区 | `#F5F6F8` | 大层级容器，保持白色卡片可辨 |
| 边框与分隔 | `#DEE0E3` | 细边框、分隔线 |
| 规划强调 | `#D48806` | 搭配“规划／后续建设”文字 |
| 规划底色 | `#FFF7E6` | 小面积标出未来能力 |

当前与规划可以用不同颜色，但必须保留文字标签。同篇中相同含义使用相同颜色；颜色不代替事实状态。

## 制图与配图

- 同篇图统一标题层级、圆角、线宽、箭头、字体和卡片内边距。图标只在帮助识别模块时使用，采用同一套简单图标。
- 总览优先横向或紧凑分层布局，画布贴合有效内容，减少无意义留白。过长流程按独立问题拆分，不通过缩小字号容纳所有细节。
- 节点优先短标题加一两行说明；超量信息移入正文或表格。先确定关系，再排列卡片，减少交叉连线。
- 流程、反馈与独立执行分别明确标注。实线、虚线一旦具有特定含义，全文保持一致。
- 截图保留理解入口、操作或结果所需的区域、必要状态与上下文。统一展示宽度与短标题；并排后文字难辨时改为纵排或保留一张关键图。用于公开模板或通用示例时，不嵌入原始内部截图。
- 趋势用折线、类别数量比较用条形；统一统计期、轴、单位与图例，有目标线时注明目标口径。少量精确数字仍用表格，不为装饰而制图。
- 预览时检查：正常文档宽度下文字可读、无重叠裁切、分组边界清楚、连线能追踪、规划标记明确。图表需要大幅放大才能理解时，应继续简化。
