# 页面模式与视觉规划

## 选择主线

下表是可组合的章节候选，按现有材料增减，空缺不靠编造填满。参考模板决定有效结构与样式，内容仍来自用户和实际资料。

| 读者任务／体裁 | 建议阅读顺序 | 适合的展示 |
|---|---|---|
| 理解技术、论文与实现 | 解决什么问题 → 核心机制 → 一次完整过程 → 论文与代码对应 → 效果及边界 → 依据 | 机制图、对照表、源码折叠 |
| 查阅系统设计 | 需求与约束 → 组件职责 → 数据流与 API → 取舍 → 运行与故障处理 | 架构图、时序图、接口表 |
| 选择方案／形成决策 | 结论与适用条件 → 比较标准 → 候选与证据 → 取舍和风险 → 下一步 | 并列列、决策表、关键限制 Callout |
| 阅读研究／实验报告 | 问题与假设 → 方法与样本 → 结果 → 解释 → 局限 → 后续 | 指标表、结果图、方法附录 |
| 复盘业务与运营 | 当前判断 → 指标及变化 → 分组证据 → 可解释因素 → 决策与行动 | 少量指标卡、趋势图、行动表 |
| 开展项目／跟踪工作 | 目标与状态 → 当前优先项 → 负责人和里程碑 → 风险与依赖 → 决定记录 | 简短状态 Callout、任务库或清单、时间线 |
| 阅读会议／周报 | 决定与重要变化 → 主题摘要 → 行动项 → 分会议记录与来源 | 行动表、主题分组、原始记录折叠 |
| 学习操作步骤 | 前置条件 → 操作 → 预期结果 → 常见问题 → 参考 | 编号步骤、代码块、实物截图 |
| 浏览知识入口 | 主题与当前重点 → 少量导航 → 各子页简介 | 子页链接、分类列表、紧凑表格 |
| 预算、漏斗或业务记录 | 口径和假设 → 实际值与目标 → 差异／阶段 → 风险 → 动作 | 数值表、数据库与视图；复杂计算保留源表 |
| 对外说明或个人作品 | 具体定位 → 经核实的能力／经历 → 案例与证据 → 适用对象／必要行动 | 图文段落、案例分栏；不默认加入营销口号 |
| 叙事或知识故事 | 读者疑问 → 场景／问题 → 转折与机制 → 意义 | 连续章节与一致插图；不把材料改写成虚构经历 |

需要法律、投资等专业内容时沿用用户要求的专业结构与证据标准；排版模板不能提供专业结论。

## 密度与风格分开决定

- 新手：一次解释一个关键概念，首次术语短定义，用小例子连接机制。
- 决策者：判断、条件和下一步先可见，完整证据放后续正文或折叠。
- 专业读者：保留字段、假设、版本和实现依据，用清晰分组支撑较高密度。
- 混合读者：上层摘要加下层技术细节；折叠不隐藏决定必需的证据。

正式文档以段落、标题与表格为主；知识文档可加克制的 Callout 与关系图；较丰富的图文页按段落目的放图。无固定图片、卡片、章节或字数配额。

结构与配色独立：比较可以用表格、两列或图；“技术”不自动等于蓝色，“Notion 风格”不自动等于手绘插画。已有风格优先延续；用户明确要求换风格时同时调整密度、层级和布局。

信息的形状决定布局：先后关系用步骤／时间线，精确比较用表，分类用同层级分组，交叉判断用矩阵，中心与周边关系用辐射图，逐层收敛用漏斗，反复运行用循环。每种结构可由原生块或兼容 Mermaid 表达，无需渲染成一整张信息图。

## 简短规划示例

```text
读者：首次接触系统的工程师
任务：理解请求经过哪些模块、在哪里继续读证据
主线：动机 → 机制 → 请求过程 → 接口对照 → 边界
密度：正文中等，代码与参数折叠
视觉焦点：请求流程图；接口表支持精确查阅
语义颜色：输入蓝／存储绿／使用紫；标签也写明角色
保留：原图、来源链接、版本与现有子页面
```

规划只记录能改变设计选择的内容。局部纠错不需设计说明，完整规划也无需另设审批或风格选择环节。

## 版面节奏

标题与章节应能单独组成有意义的大纲。每节先给关键信息，再展开证据；图与对应说明相邻。交替使用适合内容的段落、表格和图，避免全文碎成等宽卡片。

分栏只承载同层级内容，保持标题与字段顺序一致。长解释不要挤到窄列；表格不放整段文章。不要靠大量空行、分隔线、emoji 或背景色制造层级。

颜色和状态全文一致；异常用标签和说明同时标出。小字号、弱对比、超宽图会降低可读性。原生页面不能调任意排版参数时，缩短标签、拆图或减少列数。

## 持续维护

维护概览时把新事实合入对应章节，避免不断追加同一事项的更新日志。日期明确的会议和决定保留为记录，概览链接到它们。完成状态依据实际完成标准；风险、已完成事项和未解决项仍能追溯。

长页确实妨碍查阅、且当前任务包含组织页面时，可拆出子页并保留简短导航。相同标题不证明重复内容；合并前比较事实、来源和状态。链接子页、折叠章节与移动原页面有不同语义，不互相假冒。

已有偏好可以直接沿用；无偏好时选择适合内容的默认版式，不强制用户建立配置文件。把偏好写成可复用的设计选择，不在公开资源中保存私人页面 ID、账户信息或凭据。
